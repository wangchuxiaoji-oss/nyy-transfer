# Admin 管理后台完整改进计划

状态：已确认方案，待实施
制定日期：2026-07-21
关联文档：`UI_PRODUCT_IMPROVEMENT_PLAN.md`、`UI_MOBILE_REPAIR_PLAN.md`、`../product/PRD.md`

## 1. 已确认决策

| 决策项 | 最终选择 |
| --- | --- |
| 实施范围 | 一次性完整改造，不只修补高风险问题 |
| 信息架构 | 运营与系统分区 |
| 移动端列表 | 紧凑列表 + 详情抽屉；异常队列可使用大卡片 |
| 分页 | 混合分页：默认游标，精确筛选后支持页码和按需总数 |
| 低价值功能 | B 账号移到诊断页；移除管理员计划筛选；邮件升级为可处理队列；全局统计折叠 |
| 管理员体系 | 保持单管理员，增加完整操作审计，并保留未来多管理员扩展能力 |
| 批量操作 | 仅支持可逆安全操作：批量封禁/解封、举报处理、邮件重试；不提供批量删除 |
| P1/P2/P3 | 与核心后台改造同步实施 |
| 历史数据 | 近 180 天热数据；更早终态分享进入归档，仍可查询 |
| 注册 IP | 与其他行为 IP 一样保留 180 天，之后删除 |
| 管理员审计 | 审计内容长期保留；审计 IP 与 UA 在 180 天后清空 |

本计划不存在待产品确认项。实施中若出现会改变上述决策、数据保留范围、危险操作能力或信息架构的新选择，必须暂停并再次确认。

## 2. 改造目标

### 2.1 产品目标

- 把后台从“多个管理功能平铺页”升级为“任务优先的运营工作台”。
- 让分享审核、举报处理、用户管理、邮件失败处理形成可追踪闭环。
- 明确区分页面预解析、页面打开、真人互动、获取链接和管理员预览。
- 桌面端保持高密度操作效率，移动端支持查看、筛选和低风险处置。
- 所有关键管理员操作可追责、可解释、可审计。

### 2.2 规模目标

以下是由“每日新增分享 1000+、热数据 180 天”推导的最低验收基线，不是新增产品范围：

- 热分享数据不少于 180,000 条。
- 来源与访问事件不少于 5,000,000 条。
- 下载/取链日志不少于 2,000,000 条。
- 注册用户不少于 1,000 条，其中活跃用户不少于 100 条。
- 单分享支持 1,000 个逻辑文件或大量分片时，后台列表仍只读取摘要。

### 2.3 工程目标

- 默认分享列表查询 p95 小于 300ms。
- 组合筛选与搜索查询 p95 小于 500ms。
- 单 IP 关联查询 p95 小于 800ms，并明确是否截断。
- 后台首屏在接口正常时 2 秒内出现可操作任务内容。
- 移动端 390px 宽度下无页面级横向滚动。
- 同一取链动作只增加一次下载计数。
- 任一非鉴权接口失败不能导致管理员被退出登录。

## 3. 范围与非目标

### 3.1 本轮包含

- Admin 信息架构、桌面 UI、移动 UI、错误与加载状态。
- 分享、用户、举报、邮件、配额、下载、豆包、诊断模块。
- 混合分页、搜索、组合筛选、排序、批量安全操作。
- 管理员操作审计。
- P1/P2/P3 访问识别与 Nginx 日志归档。
- 热数据与归档数据分层。
- 查询索引、事件分区、统计缓存、后台任务单实例化。
- 管理员预览按需签发文件 URL。
- 完整自动化测试、性能验证、迁移和回滚方案。

### 3.2 本轮不包含

- 多管理员角色、权限矩阵或审批流。
- 批量删除分享、批量软删除用户等危险操作。
- 实际对象存储下载完成回执；下载口径仍以“成功签发链接”为准。
- 外部商业 BI、独立数据仓库或第三方风控 SaaS。
- 普通用户端产品结构重做。

## 4. 信息架构

### 4.1 顶层结构

保留 `/admin` 和 URL 状态，但导航改为分组，不拆成多个独立应用。

**运营**

- 总览
- 分享
- 举报
- 用户
- 邮件

**系统**

- 配额
- 下载
- 豆包
- 诊断

### 4.2 总览页

总览不再永久展示八张等权累计指标卡，改为三层：

1. 待处理任务：待处理举报、异常访问、邮件失败、豆包失效。
2. 今日趋势：新增分享、取链次数、真人访问、预解析、上传字节。
3. 折叠累计数据：累计用户、累计分享、累计创建字节、封禁总数。

要求：

- 待处理任务必须可点击并带入对应筛选条件。
- 异常指标使用明显但克制的告警色，不与普通累计指标等权。
- 进入分享、用户等模块后，全局统计默认折叠，业务内容进入首屏。
- “刷新”刷新当前模块与总览摘要，不再只刷新统计和配置。

## 5. 模块详细方案

### 5.1 分享管理

#### 桌面端

- 使用固定表头的紧凑表格。
- 默认列：短码/标题、身份、状态、创建时间、到期时间、文件摘要、容量、真人访问、预解析、取链、操作。
- 来源 IP、地区、运营商只显示一行摘要，完整信息进入详情抽屉。
- 长标题和来源使用省略号，行高保持稳定。
- 默认排序为 `created_at DESC, id DESC`。

#### 移动端

- 使用两行紧凑列表，不使用当前大卡片作为全量列表。
- 第一行：短码/标题、状态、创建时间。
- 第二行：身份、文件数/容量、真人访问/取链摘要。
- 点击整行打开详情抽屉。
- 危险操作不直接堆在每一行；进入抽屉后执行。
- 待处理异常列表可以使用大卡片，突出风险和主操作。

#### 搜索与筛选

- 短码：精确或前缀搜索。
- 标题：模糊搜索。
- 身份：邮箱、游客标识。
- IP：统一进入 IP 调查能力，不只查创建 IP。
- 状态：有效、耗尽、过期、撤销、封禁，互斥且共用同一状态表达式。
- 日期：创建时间范围、到期时间范围、最近活动时间范围。
- 文件：文件数范围、容量范围。
- 风险：有举报、异常 IP、仅预解析、真人取链、无访问。
- 支持把筛选状态写入 URL，刷新和分享链接后可恢复。

#### 行级操作

- 完整查看。
- 查看来源与关联。
- 封禁/解封，必须填写或选择原因。
- 举报联动封禁时自动引用举报原因。
- 所有操作显示 pending 状态，防止双击。

#### 批量操作

- 批量封禁。
- 批量解封。
- 支持选择当前页或当前筛选结果，但必须显示预计影响数量。
- 批量操作使用幂等任务 ID，重复提交不能重复执行。
- 每次批量操作写一条批次审计和逐目标结果。
- 不支持批量删除或批量撤销。

### 5.2 分享详情与管理员预览

- 详情抽屉只加载分享元数据、状态、摘要和事件第一页。
- 文件列表分页，不在列表接口中加载全部文件和分片。
- 管理员预览首次进入不签发全部下载 URL。
- 选中文件或点击下载时才为对应逻辑文件签发 URL。
- 多分片签发增加并发上限，避免对豆包服务形成瞬时洪峰。
- 管理员预览记录为 `admin_review`，不计入公开访问和下载次数。
- 预览状态横幅继续保留“不会恢复分享、不计下载次数”说明。

### 5.3 来源、IP 与行为时间线

- 事件统计与事件列表分开查询。
- 总事件数、独立 IP、真人访问、预解析和取链数必须是完整统计，不受事件页大小影响。
- 事件列表使用游标分页。
- IP 关联先在数据库中按用户、分享、游客标识去重，再限制数量。
- 关联结果返回 `has_more`、截断原因和下一游标。
- 所有 IP 调查支持时间范围，默认近 30 天，可扩到热数据 180 天。
- 共享 NAT、代理、云厂商节点必须显示误判提示。
- `T7`、`MicroMessenger` 不能只凭 UA 标记机器人。

### 5.4 举报队列

- 默认进入待处理举报，不再只是只读列表。
- 列表显示分享摘要、举报原因、举报时间、来源 IP、累计举报数、当前分享状态。
- 可直接打开管理员预览和来源抽屉。
- 行级操作：标记已处理、驳回、封禁分享。
- 批量操作：批量处理、批量驳回、批量封禁。
- 处理时记录备注、处理结果、审计日志。
- 不引入多管理员分派字段；审计仍记录当前唯一管理员。

### 5.5 用户管理

- 移除管理员计划筛选。
- 列表默认列：邮箱、计划、状态、注册时间、最近登录、注册来源摘要、最近登录来源摘要。
- 注册来源和登录来源只保留 180 天；超期显示“已按隐私策略清除”。
- 用户来源查询使用每用户一次注册、一次最近登录，不读取整段认证历史。
- 支持邮箱、计划、状态、创建日期、最近登录日期筛选。
- 行级操作保持禁用/启用、软删除/恢复、验证状态、发送重置邮件。
- 所有操作增加 pending、防重复和审计。
- 不增加批量禁用、批量软删除。

### 5.6 邮件处理队列

- 从只读列表升级为可操作队列。
- 按状态、邮件类型、失败原因、日期和收件人搜索。
- 相同错误聚合显示数量，支持展开具体投递记录。
- 行级和批量操作只提供“重试失败邮件”。
- 每次重试生成新的投递尝试记录，不覆盖原失败记录。
- 展示投递 ID、首次创建时间、最后尝试时间、尝试次数和错误摘要。
- 重试操作写入管理员审计。

### 5.7 配额与下载配置

- 继续保留现有能力，不改变配置含义。
- 游客和注册用户规则分成清晰分组。
- 保存按钮在桌面首屏可见，移动端使用底部粘性保存栏。
- 修改后显示“有未保存更改”。
- 保存前展示变更摘要和影响范围。
- 字节换算继续显示实际字节值。
- 配置更新写入审计，保存前后值。

### 5.8 豆包与诊断

- 豆包主页面只保留生产 Session 的状态、验证和刷新流程。
- B 账号互读实验移动到“诊断”。
- 诊断模块默认折叠，并标记“开发/维护工具”。
- Session 状态优先显示：是否可用、最近验证、预计到期、最近错误。
- 完整 ISO 时间放入详情或复制入口，默认使用本地时间和相对时间。
- 扫码流程重排为：开始刷新 → 二维码/倒计时 → 扫码状态 → 保存结果。
- 移动端必须说明同设备无法直接扫码，并提供第二设备或系统相册识别提示；不承诺实现豆包 Deep Link。
- 同步 `time.sleep` 改为异步等待。
- 扫码任务状态移入 Redis，使用分布式锁，支持进程重启和多 worker。
- Session 文件使用临时文件 + 原子替换。

## 6. 混合分页设计

### 6.1 默认模式：游标分页

适用：分享、用户、举报、邮件的最新数据流。

- 请求参数：`limit`、`after`、`before`、`sort`。
- 排序必须包含唯一 ID，例如 `created_at DESC, id DESC`。
- 响应包含 `next_cursor`、`prev_cursor`、`has_more`。
- 不默认执行精确总数 COUNT。
- UI 显示“已加载 N 条”和继续加载/上一批，不显示虚假精确页码。

### 6.2 精确模式：筛选页码

适用：管理员明确输入搜索、日期范围或组合筛选后定位历史数据。

- 请求参数：`page`、`page_size`、`include_total=true`。
- 只有明确筛选范围后才允许精确总数。
- 深页必须有最大范围保护；超出后提示收窄日期或搜索条件。
- 页码模式同样追加唯一 ID 排序，避免并列值漂移。

### 6.3 统一响应

列表响应至少包含：

- `pagination_mode`：`cursor` 或 `page`。
- `items`。
- `next_cursor`、`prev_cursor`、`has_more`。
- `page`、`page_size`、`total`。
- `total_is_estimated`。

不适用字段返回 `null`，前端不得自行猜测分页模式。

## 7. P1/P2/P3 访问识别

### 7.1 P1：事件分层

事件类型统一为：

- `preview_fetch`：链接预解析或疑似预览。
- `page_rendered`：浏览器完成 JS 加载。
- `human_interaction`：首次可信点击、触摸或键盘操作。
- `link_issued`：成功签发下载链接。
- `admin_review`：管理员预览。

每条事件增加：

- `client_kind`：`human`、`preview_bot`、`suspected_preview`、`unknown`、`admin`。
- `confidence`：高、中、低。
- `detector`：命中的规则名称。
- `request_id`。
- 可选 `http_status`、`request_time_ms`。

计数规则：

- 预解析不计入真人访问、独立访客和下载次数。
- `page_rendered` 代表可执行 JS 的页面访问，不直接等于真人。
- `human_interaction` 和 `link_issued` 是较强使用意图。
- 管理员预览完全独立。

### 7.2 P2：Nginx JSON 日志

为 `nyy.app` 单独定义 JSON 日志，记录：

- 时间、host、request ID。
- 客户端 IP、请求方法、路径、状态码。
- 请求耗时、上游耗时。
- UA、Referer。
- `Sec-Fetch-Site`、`Sec-Fetch-Mode`、`Sec-Fetch-Dest`、`Sec-Fetch-User`。

识别规则：

- `QQUrlRichService`：高置信 `QQ 预解析`。
- 已知 Telegram/Discord/Slack/Facebook/X 等预览 UA：高置信预解析。
- `T7`、`MicroMessenger`：只作为弱信号。
- 云厂商 ASN + 只请求 HTML + 无 JS 埋点 + 短时间多节点跳转：中置信疑似预览。
- `499` 只说明客户端提前断开，不能单独判定机器人。

使用独立日志增量任务按 inode + offset 读取，支持日志轮转和断点恢复。导入任务使用唯一事件指纹去重，不在 Web worker 内直接 tail 文件。

### 7.3 P3：后台呈现

- 灰色：预解析。
- 蓝色：页面打开。
- 绿色：真人互动。
- 橙色：获取链接。
- 紫色：管理员预览。

分享摘要显示：`页面打开 / 真人互动 / 取链 / 预解析`。

时间线可展示“QQ 预解析 → 8 秒后页面打开 → 12 秒后获取链接”，但只做时间关联展示，不把不同 IP 强制合并为同一身份。

## 8. 下载计数与幂等

- 将有副作用的公开取链接口改为 POST 语义。
- 客户端每次用户操作生成 `X-NYY-Link-Request-ID`。
- 服务端以分享 ID + 请求 ID 建立唯一约束或 Redis 幂等键。
- 同一请求 ID 重试返回第一次结果，不重复增加下载计数，不重复写日志。
- 页面初始化不得自动触发取链。
- 管理员预览使用独立接口，不共享公开计数路径。
- 迁移期间保留旧接口只用于当前前端过渡；新前端验证完成后再移除旧路径。

## 9. 数据模型与索引

### 9.1 摘要字段

分享表增加或维护以下摘要，避免列表加载关系：

- `logical_file_count`。
- `stored_object_count`。
- `last_activity_at`。
- 可选累计事件摘要，由异步聚合或写入时更新。

历史数据必须后台分批回填，禁止单事务锁住整张分享表。

### 9.2 核心索引

- `shares(created_at DESC, id DESC)`。
- `shares(total_bytes DESC, id DESC)`。
- `shares(download_count DESC, id DESC)`。
- `shares(ip_created_from)`。
- 终态/有效状态需要匹配实际查询条件的部分或组合索引。
- `reports(status, created_at DESC, id DESC)`。
- `email_deliveries(status, created_at DESC, id DESC)`。
- `download_logs(ip, downloaded_at DESC)`。
- `auth_events(user_id, event_type, success, created_at DESC)`。
- `share_access_events(share_id, event_type, created_at DESC)`。
- `share_access_events(ip, created_at DESC)`。

标题、邮箱等模糊搜索使用 PostgreSQL `pg_trgm` GIN；短码优先精确/前缀索引，不使用无差别 `%ILIKE%`。

### 9.3 事件分区

- 来源事件、下载日志按月分区。
- 热窗口保留 180 天。
- 超期访问、登录、注册、下载 IP 通过删除旧分区或分批清理完成。
- 不再每天重复 UPDATE 已经清空 IP/UA 的旧行。
- 后台任务通过 PostgreSQL advisory lock 或唯一 worker 保证单实例执行。

## 10. 热数据与归档

### 10.1 热数据

- 最近 180 天分享和运营事件。
- 所有仍有效、未到期的长期分享，即使创建超过 180 天也继续留在热表。
- 管理后台默认只查询热数据。

### 10.2 归档条件

终态分享满足以下条件后归档：

- 已过期、撤销或封禁。
- 最后活动时间超过 180 天。
- 不存在未处理举报或进行中的运营任务。

### 10.3 归档内容

- 分享基本元数据、状态、文件摘要、所有者引用和长期管理员审计引用。
- 不保留超过 180 天的注册、登录、访问、下载和审计请求 IP/UA。
- 归档数据仍可通过明确的“历史归档”入口查询。
- 归档默认只读，不恢复公开链接。

### 10.4 初始实现

- 第一版归档仍放在同一 PostgreSQL 实例的独立归档表/Schema，便于事务、备份和查询。
- 归档任务先支持 dry-run，输出候选数量和示例，不直接执行。
- 归档操作分批提交，并记录归档批次和结果。

## 11. 管理员操作审计

新增追加式审计记录，至少包含：

- 操作 ID、发生时间、请求 ID。
- 管理员用户 ID/邮箱。
- 操作类型。
- 目标类型和目标 ID。
- 操作前值、操作后值。
- 原因、备注、批次 ID。
- 成功/失败状态和错误摘要。
- 请求 IP、UA。

审计规则：

- 审计主体、动作、目标和前后值长期保留。
- 请求 IP 与 UA 在 180 天后清空。
- 审计日志不可通过普通后台接口修改或删除。
- 配额、下载配置、封禁、用户状态、举报处理、邮件重试、豆包 Session 更新都必须写审计。
- 单管理员约束保持不变，但模型预留 actor ID，不把邮箱硬编码进审计结构。
